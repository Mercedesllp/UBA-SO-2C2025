# Chapter 5 - Scheduling

Nonpreemptive or cooperative: The process keeps the CPU until it releases it either by terminating or switching to a waiting state.

Preemptive: It shares the CPU among all processes all the time

Preemptive scheduling can result in race conditions when data are shared among several processes.  
Kernels are redesigned for preemptive schedulers (for ex mutex).

Dispatcher: Module that gives control of de CPU's core to the process selected by the CPU scheduler. Switches the context from one process to another, switches to user mode, jumps to the proper location in the user program to resume the program.

Criteria for choosing an scheduling algorithm:

- CPU utilization (maximize)
- Throughput (maximize): Number of processes that are completed per time unit.
- Turnaround time (minimize): Interval from the sum of the time waiting on the ready queue, the time running, and doing I/O.
- Waiting time (minimize): Sum of the periods sepnt waiting on the ready queue.
- Response time (minimize): Time between ready and running for the first time.

The min or max can change the importance depending on the tasks.

Scheduling Algorithms for processes:

- FCFS: The process that requests the CPU first is allocated the CPU first. Managed by a FIFO queue. Generates a convoy effect and waiting time is horrible. The algorithm is nonpreemptive. Troublesome for interactive systems.
- SJF (Shortest Job First): It takes the process that has the smallest next CPU burst. It uses prediction based on previous CPU bursts of the process. Can be preemptive or nonpreemptive, if preemptive then if a shorter process comes after the current one, then it changes.
- RR (Round-Robin): Similar to FCFS but preemptive. The ready queue is treated as a circular queue allocating the CPU to each process for a time interval of up to 1 time quantum. The performance depends heavily on the size of the time quantum (if large it beacomes FCFS, if short, there would be a lot of context switches which is costly and poorly productive).
- Priority scheduling: Priority to each process, the CPU is allocated to the one with the highes priority, equal priority uses FCFS or RR. There are internal (measurable quantity or quantities to compute the priority) and external (set by a criteria outside the OS, such as the importance of the process) priorities. Could be preemptive (interrupting the current process to see if the new one has a higher priority) or nonpreemptive. A problem is starvation.
- Multilevel Queue Scheduling: With priority and RR scheduling, all processes may be placed in a single queue, and the scheduler then selects the process with the highest priority to run. A common division is made between foreground (interactive) processes and background (batch) processes, different algorithms could be used in different queues.
- Multilevel Feedback Queue Scheduling: Allows processes to move between queues, being able to move up in priority, we could use aging to avoid starvation.

Convoy effect: All the processes wait for the big one yo get off the CPU.

Starvation or infinite blocking: The process waits indefinitly being ready.

Thread Scheduling

Multiple-Processor Scheduling:

- Assymetric multiprocessing: There is a master processor in charge of the scheduling.
- Symmetric multiprocessing (SMP): Each processor is self-scheduling. It could have a common ready queue for all threads or a private queue of threads for each prrocessor (first one could have race conditions; the second one is better but it could have workloads of varying sizes - for this there are balancing algorithms). 

---
Multicore processors

Memory stall: When a processor accesses memory, it spends a significant amount of time waiting for the data to become available.

Chip multithreading (CMT): A processor divided by cores which contain an amount of hardware threads that end up seeming like logical CPUs to the OS.

Hyper-threading or simulatenous multithreading (SMT): Assings multiple hardware threads to a single processing core.

Ways to multithread a core:

- Coarse-grained: A thread executes on a core until a long-latency event occurs. Costly to exchange threads.
- Fine-grained: Switches between threads at a much finer level of granularity. The cost of switching between threads is small.

There are two levels of schedulings in multithreaded systems, for software threads and for hardware threads.

---
For Load Balancing there are two general approaches (not exclusive to each other):

- Push migration: A specific task periodically checks the load on each processor and evenly distributes the load by moving (or pushing) threads from overloaded to idle or less-busy processors, if there is an imbalance.
- Pull migration: An idle processor pulls a waiting task from a busy processor.


Processor affinity: A process has an affinity for the processor on which is currently running (because of warm cache). There is soft and hard affinity for the policies of which processes can be part of load balancing and in which processors, there are syscalls for this.

Heterogeneous multiprocessing

Systems designed using cores that run the same instruction set, yet vary un terms of their clock speed and power management (including the possibility of idling the core). Bakcground tasks can be assigned to  little cores and interactive application can be assigned to big cores.

Real-time CPU scheduling

- Soft real-time systems: Provide no guarantee as to when a critical real-time process will be scheduled. Only it's given a certain priority.

- Hard real-time systems: A task must be serviced by its deadline.

Dispatch latency: Time required for the scheduling dispatcher to stop one process and start another.

Algorithms for scheduling hard real-time systems:

- Rate-monotonic scheduling: Priority to the shortest process.

- Earliest-Deadline-First scheduling (EDF)

- Proportional share scheduling: Divides in shares of time and gives each process a quantity for its excecution if another one wants to execute first there must be enough shares to this one, if there is not, the **admission controller** would deny its entry into the system.

- POSIX real-time scheduling
