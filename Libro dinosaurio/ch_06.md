# Chapter 6 - Syncronization tools

Cooperating process: can affect opr be affected by other processes executing in the system.

Race condition: The outcome of the execution depends on the particular order in wich the access takes place.

Requirements to the critical-section problem:

- Mutual exclusion
- Progress: Selection of the process to enter the critical section
- Bounded waiting: Limit on the number of times that other processes can access a critical sections and the actual process couldn't.

---

Hardware support for sincronization:

- Memory barriers: Uses an application program known as its memory model (strongly ordered and weakly ordered). Used to communicate a memory change across the processors. Only used by kernel developers.

- Hardware instructions: `test_and_set(boolean *target)` and `compare_and_swap(int *value, int expected, int new_value)` atomic instructions

- Atomic variables: Provides atomic operations on basic data types

---

Hig-level software tools to solve the critical-section problem:
- Mutex locks / Spinlocks: A lock that can be acquired and released. Implemented with busy waiting.
- Semaphores: Integer variable that, apart from initialization, is accessed only through two standard atomic operations (`wait()` and `signal()`). Can be used as mutex locks. Uses `sleep()` and `wakeup()` to implement `wait()` and `signal()`. Not always good because of timing errors if incorrectly used.
-  Monitors: 

Lock contention: If no threads are trying to acquire the lock, then it's uncontended, otherwise it's contended. Con have low or high contention depending on how many want the lock.

busy waiting: Wastes CPU cycles waiting.

short duration for a spinlock is a duration less than two context switches.

Abstract data type (ADT): Encapsulates data with a set of functions to operate on that data that are independent of any specific implementation of the ADT.

Monitor type: An ADT that includes a set of programmer-defined operations that are provided with mutual exclusion within the monitor.

Liveness: Set of properties that a system must satisfy to ensure that processes make progress during their execution life cycle.

Deadlock: Every process in the set is waiting for an event that can be caused only by another process in the set.

Priority inversion: The process of higher priority can't use a resource beign used by processes of lower priority. It's fixed with a priority-inherentance protocol, where the process using the resource inherets the priority of the requesting process briefly.
